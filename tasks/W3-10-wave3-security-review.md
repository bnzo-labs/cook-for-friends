## Checklist (each item → PASS / finding with severity)
- Every `/api/{video,progress,certificates,materials,comments,enrollments,waitlist}/**` route: authn, authz (owner vs other customer vs staff), Origin check on POST, rate limits, zod at boundary, error envelope leaks nothing (no stack, no existence oracle).
- Video: playback only with active entitlement (or preview + signed-in), TTL ≤ 2 h, URL never cached/logged/SSR'd; Mux JWT claims; webhook signature + timestamp tolerance; fake provider unreachable when `VIDEO_PROVIDER ≠ fake` and env guard blocks `fake` without `VIDEO_FAKE_ALLOWED`.
- Materials: presign TTL 300 s, key never user-controlled, entitlement via any containing course only.
- Cancellation: concurrency (double click, two tabs, staff + buyer same time), Stripe failure/retry idempotency (`seat-cancel-<id>`), `amount ≤ seatAmount − refunded`, guest cannot cancel, credit code single-use + personal + unguessable, `charge.refunded` replay.
- Comments: stored XSS (render path), parent spoofing, rate limits, moderation bypass via REST (`status` field access), PII in listing.
- Reminders/waitlist: no email enumeration, exactly-once delivery, PII retention (waitlist emails — note a retention rule for Wave 4 if none).
- Certificates: verify page reveals only name/course/date; PDF route ownership; code entropy.
- Portal: `no-store` on all account responses, SW never caches account/api (inspect `public/sw.js`), magic-link token not in logs/history, `next` open-redirect.
- Secrets: no Mux/R2 keys in client bundles (`grep` the `.next/static` build output).
